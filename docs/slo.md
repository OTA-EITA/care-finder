# SLO

利用者（ご家族）にとって大事なのは「探せること」と「事業所の情報を開けること」。ログインやお気に入りは、止まっても探すことはできる。そこで、検索と詳細ページを対象に SLO を置く。

## 対象と指標

| SLI | 測り方 | SLO（28 日間） |
|---|---|---|
| 可用性 | ALB のリクエストのうち 5xx でない割合（`/up` を除く） | 99.5% |
| レイテンシ | `GET /facilities` と `GET /facilities/:id` の応答時間 p95 | 800ms 以下 |

- 99.5% のエラーバジェットは 28 日で約 3 時間 21 分ぶん
- 応答時間は ALB の `TargetResponseTime`（全体）で監視し、内訳は lograge の JSON ログ（`duration`、`db`、`view`）と OpenTelemetry のトレースで見る

## アラート（infra/terraform/monitoring.tf）

| アラーム | 条件 | 意味 |
|---|---|---|
| `alb-5xx-rate` | 5 分ごとの 5xx 割合が 2% 超を 2 回連続 | バジェットを約 4 倍の速さで消費している |
| `alb-latency-p95` | p95 > 800ms が 15 分続く | レイテンシ SLO を割りそう |
| `unhealthy-hosts` | `/up` に失敗するタスクが 3 分続く | タスクの起動失敗・メモリ不足など |
| `jobs-not-running` | ジョブのタスクが 0 | 索引更新とメールが止まる |
| `aurora-cpu` / `aurora-acu-near-max` | CPU 80% 超、上限 ACU の 90% | DB が詰まりかけている |
| `redis-memory` | メモリ 80% 超 | キャッシュの追い出しが増える |

## 劣化したときの動き

- **Elasticsearch に接続できない**（SEARCH_BACKEND=elasticsearch のとき）: MySQL の全文検索で続け、画面に「簡易検索」と出す。ログには `search.fallback` が出る
- **Redis に接続できない**: キャッシュなしで動く。`rate_limit` の回数も数えられなくなるため、ログインの総当たりは WAF のレート制限で止める。ログには `cache.error` が出る
- **国土地理院 API に接続できない**: 駅名の一覧だけで距離を出す（3 秒でタイムアウト）
- **DB に接続できない**: 検索も詳細も出せない。`/up` は DB に触らないので ALB からタスクは外れず、5xx の割合でアラームが鳴る

## 見直し

- 月に 1 回、エラーバジェットの残りと、アラームが鳴った回数（誤報を含む）を見る
- バジェットを使い切りそうなら、新機能より信頼性の改善を先にする
